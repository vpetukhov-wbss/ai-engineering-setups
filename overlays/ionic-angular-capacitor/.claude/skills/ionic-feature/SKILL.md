# ionic-feature

1. Read acceptance criteria and current code; define loading, empty, offline, stale, error, permission-denied and unauthorized UI states.
2. Use project-consistent standalone Angular, imports from @ionic/angular/standalone, focused feature folders and separate TS/HTML/SCSS/spec files.
3. Honor Ionic page structure, touch targets, keyboard and safe areas. Keep domain validation authoritative on backend.
4. Use signals for local synchronous state, RxJS for streams/cancellation, and narrow native adapters; avoid duplicate stores and generic helpers.
5. Add tests of success, retry, permission denial and web fallback; run installed scripts, web production build, native compile/device verification when available.

## Proof of completion
Provide changed files, exact commands/results, platforms verified, platforms NOT TESTED, risks, and human approvals still needed. Never claim a device or App Store submission was tested if it was not.
