# angular-test-strategy

## Procedure
1. Discover installed unit/e2e runners and CI, features, security threats and release risk.
2. Prioritize tests for business critical journeys, forms, state races, routing/guards, auth and API failures.
3. Use TestBed/component harness and HTTP mocks where appropriate; add contract/integration tests for shared backend behavior.
4. Test UI with Playwright/Cypress if configured; use stable locators and seeded nonproduction data.
5. Run actual scripts and capture artifacts/repro steps, coverage gaps and verified-vs-planned distinctions.

## Deliverables
Summarize scope and choices, changed files, verified commands/results, evidence, risks and required human approvals.
